## 数据格式（Schema）

每个 JSON 文件是一个**数组**，里面放多首诗词对象：

```json
[
  {
    "id": "song-xu-0001",
    "title": "念奴娇·赤壁怀古",
    "author": "苏轼",
    "dynasty": "宋",
    "form": "词",
    "content": [
      "大江东去，浪淘尽，千古风流人物。",
      "故垒西边，人道是，三国周郎赤壁。"
    ],
    "translation": "",
    "notes": "",
    "background": "",
    "analysis": "",
    "appreciation": "",
    "artisticConcept": "",
    "tags": ["怀古", "赤壁", "周瑜", "豪放"],
    "theme": "豪放"
  }
]
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `id` | string | ✅ | 全局唯一 ID，格式见下方 §ID 命名规则 |
| `title` | string | ✅ | 诗词标题（词牌·首句 形式） |
| `author` | string | ✅ | 作者姓名 |
| `dynasty` | string | ✅ | 朝代，见下方 §朝代取值 |
| `form` | string | ✅ | 体裁：`诗` / `词` / `曲` |
| `content` | string[] | ✅ | 诗句正文，**每行一句**，数组形式；词的**小序**也作为数组首元素 |
| `translation` | string | 选填 | 白话翻译 |
| `notes` | string | 选填 | 注释说明 |
| `background` | string | 选填 | 创作背景 |
| `analysis` | string | 选填 | 词句赏析 |
| `appreciation` | string | 选填 | 整体艺术特色 |
| `artisticConcept` | string | 选填 | 意境分析 |
| `tags` | string[] | ✅ | 标签数组，用于关键词搜索，建议 3–4 个 |
| `theme` | string | ✅ | 主题分类，用于筛选，**必须取自下方 §主题列表** |

> 选填字段本期可先留空字符串 `""`，但**字段必须存在**（接入层不做缺字段保护的前提）。

## ID 命名规则

**格式**：`<朝代拼音>-<负责人拼音>-<4位序号>`

```
song-xu-0001
 │     │   └── 4 位序号（0001 起，按清单顺序递增）
 │     └────── 负责人拼音（hong / liu / xu / chen / zhang）
 └──────────── 朝代拼音（见下表）
```

**为什么要带负责人**：5 人各填 50 首，若都用 `song-0001` 起编，会出现 **100% ID 撞车**。
由于每人改的是不同文件，Git 不会报冲突，但 `getPoemById()` 只会返回其中一个，
**合并后 250 首实际只剩一半能用**。加上负责人段可从根上杜绝，且无需协调号段。

| 负责人 | 拼音段 |
|---|---|
| 洪修睿 | `hong` |
| 刘庭彰 | `liu` |
| 徐潇 | `xu` |
| 陈汝桐 | `chen` |
| 张雅萱 | `zhang` |

| 朝代 | 拼音段 | | 朝代 | 拼音段 |
|---|---|---|---|---|
| 唐 | `tang` | | 五代 | `wudai` |
| 宋 | `song` | | 三国 | `sanguo` |
| 元 | `yuan` | | 北朝 | `beichao` |
| 汉 | `han` | | 西晋 | `xijin` |
| 明 | `ming` | | 南朝宋 | `nanchaosong` |
| 清 | `qing` | | 东晋 | `dongjin` |

**示例**：
- 徐潇的苏轼《念奴娇·赤壁怀古》 → `song-xu-0001`
- 陈汝桐的欧阳修《蝶恋花·庭院深深深几许》 → `song-chen-0001`
- 张雅萱的马致远《天净沙·秋思》 → `yuan-zhang-0001`

## 自检方式

填完后跑一次构建，开发模式下控制台会**自动校验 ID 唯一性**：

```bash
npm run dev
```

若出现 `[poems] ID 冲突` 或 `[poems] 共 N 条，唯一 ID 仅 M 个`，说明有重复 ID，必须先修掉再提 PR。
